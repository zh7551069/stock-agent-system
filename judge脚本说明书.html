stock/judge 脚本说明书

生成时间 2026-10-25 · 数据源 taobao_minute.duckdb（当前水位 2026-10-22） · 用途：逐个确认判决器 11 个 py 文件的职责、输出与使用者
先看这个：stock/judge/ 是「判决器」——度量一条历史决策真实做对没有的确定性代码，与选手（策略/决策引擎）物理隔离。分两类：库模块（无 CLI，被 import）4 个，CLI 脚本（可命令行跑）7 个。

一、总览

脚本性质一句话功能主要使用者 / 场景
outcome.py库判决核心：复算单条决策的真实结果（剔 beta 超额、可成交性、成本毛/净）所有判决脚本的底座
bulk.py库BulkLibrary：按「信号日」批量预取 + 缓存，批量与单条结果一致baseline/probe/slice 等批量回放

baseline.pyCLI「T 日涨停 → T+1 开盘买」跨 879 独立日回放，vs 同日随机对照 + 配对 t回测判决官：给涨停规则做基线证伪

二、库模块（被 import，无 CLI）

库模块outcome.py — 事实冻结核心

给定一条决策（Decision），从主库复算它已经发生的真实结果（Outcome）。整个系统唯一合法的验收标准来源。
核心口径
T+1 开盘入场 → T+k 收盘；超额 = 个股 − 沪深300（剔 beta）；封板/停牌不可成交记为「缺失」非 0；成本毛/净两套（净 = 毛 − 0.15% 往返）。
对外对象
Decision / Outcome / Quality / judge() / summarize() / Library
输出文件
无（纯库）
使用者
其余 7 个 CLI 脚本的底座；未来「回测判决官」agent 的确定性代码。
# 单条判决的 Outcome.as_dict() 摘要
{"code": "002084.SZ", "tradable": false, "reason": "limit_up_on_open",
 "ret": {"5": null}, "excess": {"5": null}, "ret_net": {"5": null}, ...}

# summarize() → Quality.as_dict() 摘要
{"n_total": 70, "n_tradable": 63, "n_untradable": 7,
 "avg_excess": {"5": 0.0520}, "avg_excess_net": {"5": 0.0505}, ...}

库模块bulk.py — 批量缓存

把「按天取数」合并成少数几条查询；同一天所有标的的行情/涨跌停/停牌一次性取回并缓存，再逐条调用同一个 judge()。
核心保证
批量与单条判决结果必然一致（同一计算路径），只做缓存不改口径。
对外对象
BulkLibrary(Library) · prefetch_day() · universe()
输出文件
无（纯库）
使用者
baseline / probe / slice / calibrate / oracle_check / exit_sim 做批量回放。

库模块stats.py — 统计口径

刻意保持极小、无依赖：统计口径一旦分叉，跨假设的对比就不成立。
核心函数
DaySeries（按独立日携带日期）· day_series · mean · tstat(min_n=5) · paired_t / paired_diff（按日期交集配对）
钉死的坑
配对必须按日期对齐，不能按索引（同一天多股高度相关，必须先按日聚合成一个观测值）。
输出文件
无（纯库）
使用者
所有 CLI 脚本的统计层。

库模块__init__.py — 包文档

声明设计原则：本包与选手（决策/引擎）物理隔离；若与选手共享代码就共享同一个 bug，判决随之失效。
内容
仅 docstring，无功能代码。
使用者
—（文档入口）。

三、CLI 脚本

CLIbaseline.py — 基线回放（涨停买入证伪）

把「T 日涨停 → T+1 开盘买」当一条决策规则，跨多个独立日回放，与同日随机对照做配对 t 检验。
用法
.venv/bin/python judge/baseline.py --start 2023-01-01 --end 2026-08-25 --control 200 --min-samples 20
输出文件
judge/reports/baseline_{start}_{end}.json（by_horizon / by_year / per_day 逐日明细）
使用者 / 场景
回测判决官——给「涨停就买」这条最朴素的规则做基线证伪，回答「涨停本身有没有信息」。
基线回放结果 | 879 个独立日 | 对照抽样 200 只/日 | 往返成本 0.15%

CLIprobe.py — 多信号假设检验流水线

同一把尺子（相同入场/窗口/对照/配对检验）换信号即可比较，跨信号结果可比。
内置信号
limit_up / limit_down / drop5 / drop3d / new_low60 / rsi6_lt20；RANKED 类：flow_top / flow_bottom / lhb_net_top（按日横截面取分位）。
用法
.venv/bin/python judge/probe.py --start 2023-01-01 --end 2026-08-25 --signals limit_up,drop5 --control 200
输出文件
judge/reports/probe_{start}_{end}.json（每信号 by_horizon）
使用者 / 场景
因子工坊 / 策略师——快速探一个新信号有没有 alpha（进攻侧 / 恐慌侧 / 资金流）。

CLIslice.py — 分层判决（找正期望子集）

在「涨停买入」已证伪的规则里，按 7 维切分、逐桶给剔 beta 超额 + 按独立日 t 值，找是否存在正期望子集。
7 个维度
连板高度 / 涨停时间 / 封单额(三分位) / 换手率 / 实际流通市值(三分位) / 同板块家数 / 昨日是否涨停。
用法
.venv/bin/python judge/slice.py --start 2023-01-01 --end 2026-08-25
输出文件
judge/reports/slice_{start}_{end}.json（by_board/by_time/… 每桶 t5/t5_net/t20/t20_net）
使用者 / 场景
策略师——regime 分层、找有效子集（当前结论：7 维 × 20 桶无一个正显著桶）。

CLIexit_sim.py — 退出规则模拟器

同样的入场下，比较不同退出规则的真实期望——回答「机会可能不在选什么，而在怎么走」。
9 种规则

用法

输出文件
judge/reports/exit_{signal}_{start}_{end}.json（rules.{name}.treat_gross/treat_net/diff_net/paired_t_net）
使用者 / 场景

CLIcalibrate.py — 判决器自校准

证明这把尺子既能测出负、也能测出正：恒等检验 / 零假设检验 / 已知正 alpha 检验。
三关
① 恒等（自己减自己 = 0）② 零假设（随机票劈两半，差值 ≈0 不显著）③ 已知正 alpha（低换手应跑赢）。
用法
.venv/bin/python judge/calibrate.py --start 2023-01-01 --end 2026-08-25 --per-side 200
输出文件
judge/reports/calibrate_{start}_{end}.json（identity_ok / null_test / low_turnover）
使用者 / 场景
维护者——判决器上线前 / 口径变更后自校准；若测不出正号，前面所有负结论都要作废。

CLIoracle_check.py — Oracle 检验（能力下限）

故意偷看未来——每天选实际 T+k 超额最高的 N 只当处理组。正确的判决器必然给出巨大正号；测不出 = 尺子坏了。
用法
.venv/bin/python judge/oracle_check.py --start 2023-01-01 --end 2026-08-25 --sample 600 --top 150
输出文件
judge/reports/oracle_{start}_{end}.json（passed + 各 horizon diff/paired_t）
使用者 / 场景
维护者 / 评测平台——数据源或口径变更后必跑的决定性测试。

四、使用关系速记

要回答的问题跑哪个关键看什么
「涨停买入」有没有 alpha？baseline.py配对 t（涨停 − 对照）是否显著为负
某个新信号有没有 alpha？probe.py跨信号对照的配对 t
有没有哪个子集是正期望？slice.py各分桶 T+5/T+20 净超额 + t
换种出场规则会不会更好？exit_sim.py各规则差值(净) + 配对 t(净)
判决器本身可不可信？calibrate.py + oracle_check.py零假设不显著 + oracle 强正
快速看某天涨停后表现demo_limitup.py单日快照（仅供自检）
