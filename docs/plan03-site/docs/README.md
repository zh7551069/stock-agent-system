# 股票交易策略生成智能体系统

多 Agent 架构 · 自我进化 · 外挂评测平台 · 会话过程可观测

> **PLAN-03 · v3** · 架构设计方案。两段式编排：**主控**（意图/规划）+ **调度器**（运行时）。判决器先行。

## 两条纵贯线（横切关注点）

本系统有两个**横切关注点**，贯穿所有面、所有 Agent、所有任务——不是两个独立功能，而是两条纵贯线：

1. **可观测纵贯线（Observability）** — 每个 Agent 每回合都产出结构化 span（四元 id + 三层语义 + 8 类 span），写 append-only Trace 总线。一切决策可回放、可归因、可复核。
2. **自进化纵贯线（Self-evolution）** — 每个 Agent 的输出最终落到「冻结层（判决器/口径/回测引擎）+ 两个可进化层（策略/因子 + prompt/skill/协议）」；裁决面输出 → 归因 → 影子回放门禁 → 晋级/回滚。

这两条线是**同一条反馈回路的两个视角**：可观测负责「建立事实」，自进化负责「依据事实改进」。可观测是自进化的输入（归因靠 trace），自进化是可观测的目的（观测是为了改进）。详见 [可观测平台设计](/observability.html) 与 [自进化设计](/self-evolution.html)。

## 核心结论

- **Agent 总数**：13 个运行时 Agent（另 + 1 个外挂评测平台）
- **切分**：门面/决策面 6 · 裁决面 3 · 平台面 4；协议设计是治理工件，不设 Agent
- **模型主线**：DeepSeek Flash 管高频/例行/视觉；Pro 管深推理/质量/意图规划；智谱 GLM 做异源第二意见与降级冗余
- **评测接入**：Trace 总线 push → 采集/评测/反馈三层，四元 id 贯穿，平台对生产只读
- **自我进化**：trace → 分析 → 优化 → 影子回放 → 晋级/回滚，回归门禁

## 六条设计原则

1. **判决器优先、物理隔离** — 评测/回测/对账跑在与策略生成不同的进程、代码仓，只读生产数据。
2. **以「日」为独立样本** — 同日多股相关，不用交易笔数虚增自由度；配对检验对齐日期，n≥5。
3. **未经严谨考证的数据不用于决策** — 字段带口径/单位/来源/复权基准，知识卡带证据等级。
4. **先看机会再看风险，用概率与权重** — 不做"一刀否决"，判决器输出概率而非二元。
5. **复盘永远执行且基于事实** — 结果不可质疑，被质疑的是决策时的动作、抓手与依据；更差即回滚。
6. **一切过程可回放** — trace 贯穿四元 id，评测平台只看 trace 与结果。
