# Agent 清单（13 个运行时 Agent）

两段式编排：**主控**做意图理解与规划，**调度器**做运行时派发。其余按「上下文不同 / 模型强度不同 / 节奏不同 / 状态所有权不同」切分。

| # | Agent | 面 | 核心职责 | 模型 | 节奏 | 写域（所有权） |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | **主控** Commander | 门面 | 意图理解、目标/任务规划、子任务分解、结果整合、追问澄清 | DeepSeek Pro | 会话入口/按需 | 目标与任务清单 |
| 2 | **调度器** Runtime Orchestrator | 决策 | 任务路由、并发/预算、协议执行、幂等、组装决策包、触发对账 | DeepSeek Flash | 事件驱动 | 任务队列、决策包 |
| 3 | **策略师** Strategist | 决策 | 策略生成：因子假设→信号/进出场/仓位/风控门，产出机器可读 proposal | 起草 Flash · 定稿 Pro | 盘后为主 | 策略 proposal（草稿态） |
| 4 | **因子工坊** Factor Lab | 决策 | 因子定义/注册/版本、口径与来源绑定、因子 QC | Flash | 盘后 | 因子字典（Schema 注册表） |
| 5 | **大盘分析师** Macro Analyst | 决策 | 大盘大势、板块/题材轮动、消息面机会 | DeepSeek Pro | 盘后日频 | 大势研判、板块机会清单 |
| 6 | **盘中哨兵** Intraday Sentinel | 决策 | 盘中监听：涨跌停/异动/信号触发/风控阈值，触发即发事件 | Flash | 盘中实时 | 事件流（只发不落库） |
| 7 | **回测判决官** Backtest Judge | 裁决 | 回测：独立日超额、配对 vs 随机对照、分层切片；harness 是确定性代码 | 代码 + Flash 解读 | 按需 | 判决库（只读生产） |
| 8 | **对账官** Reconciler | 裁决 | 决策对账（事实：决策 vs 实际 T+N 结果）+ **结果归因**（因子/策略沿溯源图·信用传播），产出对账单 + 归因结论 + 回滚信号 | DeepSeek Pro | T+N 收盘后 | 对账单、归因结论、回滚建议 |
| 9 | **会话评估官** Process Evaluator | 裁决 | 评估会话过程（**评估器**：证据/边界/判定 + LLM Judge），trace 分析推理质量/工具效率/协议合规/成本 | Pro + GLM 异源 | 异步批处理 | 过程评测报告、过程评估结论（只读 trace） |
| 10 | **数据管家** Data Custodian | 平台 | 数据维护：本地 duckdb + 线上获取，口径/单位/复权一致性，QC 门禁 | Flash + 代码 | 盘后/按需 | 数据库、口径注册表 |
| 11 | **知识馆长** Knowledge Curator | 平台 | 知识库维护：卡片去重/溯源/证据分级，争议异源裁定 | Flash + Pro + GLM | 异步 | 知识库、证据索引 |
| 12 | **能力管家** Capability Steward | 平台 | 工具 + Skill 维护：注册/版本/契约测试，测试通过才晋级 | Flash | 按需 | 工具/Skill 注册表 |
| 13 | **资产登记官** Asset Registrar | 平台 | 会话过程资产维护：蒸馏成决策/理由/结果/教训的结构化资产 | Pro 蒸馏 + Flash | 会话结束/异步 | 过程资产库（内容寻址） |

## 两个关键设计

- **主控只规划整合，不落库、不写判决库** —— 写域由协议总线 ACL 强约束，防越权。
- **协议设计（任务 8）是治理工件** —— 由调度器执行、裁决面验证，不设运行时 Agent。

## 调度器的两个触发源

调度器是运行时总调度，但它**不是只被主控调用**——它有两个触发源：

| 触发源 | 触发方式 | 典型任务 | 特点 |
| --- | --- | --- | --- |
| **主控** | 会话入口 / 按需 | 用户意图 → 任务清单（含「派给哪个面」的规划） | 有人参与，任务来自意图 |
| **定时器** | cron 定时（盘后 / 盘前 / 定时复盘） | 盘后对账、盘前预热、定时复盘、数据 QC | 无人参与，任务来自时刻表 |

> 两者最终都落到调度器的**同一条执行路径**（任务队列 → 路由 → 并发/预算 → 幂等 → 组装决策包）。区别只在「任务从哪来」：一个来自主控的规划，一个来自定时器的时刻表。

## 每个 Agent 在两条纵贯线上的位置

可观测（Span 类型）与自进化（进化角色）是横切关注点，**每个 Agent 同时承担二者**：

| # | Agent | 可观测产出（Span 类型） | 进化角色（读/写哪个层） |
| --- | --- | --- | --- |
| 1 | 主控 | 回合 turn | 读经验（效用检索）；不写可进化层 |
| 2 | 调度器 | 回合 turn | 执行协议；不写可进化层 |
| 3 | 策略师 | 模型调用 llm + 检索 retrieve | 写可进化 A（策略 proposal、调权重/改出场） |
| 4 | 因子工坊 | 检索 retrieve + 模型调用 llm | 写可进化 A（因子字典，4 类动作） |
| 5 | 大盘分析师 | 模型调用 llm | 写可进化 A（大势研判，作为 regime 输入） |
| 6 | 盘中哨兵 | 事件 event（只发不落库） | 触发对账；不写可进化层 |
| 7 | 回测判决官 | 判决 judge + 风控校验 guard（确定性代码） | 冻结层（不可进化）；供归因统计 |
| 8 | 对账官 | 判决 judge + 模型调用 llm | 结果归因（信用传播）→ 驱动策略进化 |
| 9 | 会话评估官 | 模型调用 llm + 检索 retrieve（打标） | 过程评估（评估器）→ 驱动过程进化 |
| 10 | 数据管家 | 数据取数 data + 风控校验 guard | 冻结层（口径契约）；供 QC 门禁 |
| 11 | 知识馆长 | 检索 retrieve + 模型调用 llm | 写可进化 B（知识卡，带证据等级） |
| 12 | 能力管家 | 工具调用 tool | 写可进化 B（prompt/skill/协议） |
| 13 | 资产登记官 | 检索 retrieve（效用重排）+ 打标 | 写可进化 B（决策资产三元组 + 溯源边） |

> 规律：**决策面/平台面产出 + 写可进化层；裁决面只读 + 归因；冻结层（判决器/口径/回测引擎）永不进化。** 这条规律把「谁产生判断」与「谁验证判断」在两条纵贯线上也分开了。
