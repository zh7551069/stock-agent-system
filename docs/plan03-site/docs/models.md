# 模型选型（DeepSeek + 智谱）

原则：**高频/例行/延迟敏感 → Flash；质量优先/深推理/意图规划 → Pro；异源交叉校验与降级冗余 → 智谱 GLM。**

| 模型 | 用在哪 | 为什么 |
| --- | --- | --- |
| DeepSeek V4.1-Flash | 调度器、因子工坊、盘中哨兵、数据管家、能力管家、回测解读 | 便宜 3–4 倍、并发 2500、输出短、支持视觉 |
| DeepSeek V4-Pro | 主控、策略师（定稿）、大盘分析师、对账官、会话评估官、资产蒸馏 | 更强 agentic 编码与难推理，质量优先；无视觉 |
| 智谱 GLM-5.3-flash / flashx | 因子解读批量、数据 QC 第二遍、盘中哨兵降级冗余 | 高吞吐低成本，DeepSeek 限流/故障时兜底 |
| 智谱 GLM-5.3 | 会话评估官、知识馆长的**异源第二意见** | 两家厂商交叉校验，降低单一家族共模错误 |

::: warning 占位说明
模型版本号按你本地网关目录里实际可用的为准（GLM 名称取自 gateway 模型清单）。正式定版前，用同一批任务对 Flash / Pro / GLM 做一次配对 A/B，以实测差距为准，不以宣称的 benchmark 为准。
:::

## 模型与两条纵贯线

模型选型要同时服务「可观测」与「自进化」这两条横切线：

| 纵贯线 | 模型侧要求 | 落地 |
| --- | --- | --- |
| 可观测 | 引擎能吐 logprobs + token 级耗时/候选概率 | 选型时把「支持 logprobs」列为硬条件；评估器标签用标签 token 概率判置信度 |
| 自进化 | 精判/归因要强推理；例行/粗筛要便宜 | 多阶段评估：规则 + 统计 0 LLM，异常才 Pro 精判 |

- **评估精判**（阶段 2 LLM 复盘、会话评估的异源第二意见）用 **Pro + GLM 交叉**——评估结论影响回滚，必须稳，不能单靠一家。
- **token 级观测**：对账/评估要下探到「慢在哪个 token、偏从哪个 token 开始」，这是 Flash/Pro 都做不到的——需要**引擎内逐 token 埋点**（对标 AI Vision 的 token 级 Trace），选型时作为观测侧接入条件。
