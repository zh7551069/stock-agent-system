# 16 项任务 → Agent 映射

主控负责「入口·意图理解·规划·整合」这条元任务（任务 0，是所有任务的起点）。**「归因分析」是设计过程中新增的显式任务（任务 7）**——它是自进化链路（裁决面输出 → 归因 → 进化）的枢纽。

| 任务 | 主责 Agent | 协作 | 面 |
| --- | --- | --- | --- |
| 0 意图理解/规划/整合 | 主控 | 调度器（执行）、各 agent（供结果） | 门面 |
| 1 策略生成（技术因子） | 策略师 | 因子工坊（供因子）、回测判决官（验证） | 决策 |
| 2 知识库维护 | 知识馆长 | 资产登记官（入库格式） | 平台 |
| 3 数据维护（本地+线上） | 数据管家 | 回测判决官（口径断言） | 平台 |
| 4 工具 TOOLS 维护 | 能力管家 | 调度器（调用契约） | 平台 |
| 5 会话过程资产维护 | 资产登记官 | 会话评估官（质量信号） | 平台 |
| 6 决策对账 | 对账官 | 资产登记官（读资产）、调度器（收信号） | 裁决 |
| 7 归因分析（因子/策略沿溯源图定位错误节点） | 对账官（结果归因·信用传播）· 会话评估官（过程评估·评估器） | 回测判决官（供统计）、资产登记官（供溯源） | 裁决 |
| 8 多 agent 交互协议约定 | 协议注册表（治理工件） | 调度器执行 · 对账/评估官验证 · 版本化 | 治理 |
| 9 因子维护 | 因子工坊 | 数据管家（口径）、回测判决官（有效性） | 决策 |

| 16 regime 维度验证 | 因子工坊（定义+打标） | 回测判决官（供验证统计）、知识馆长（供断点候选）、数据管家（供数据） | 决策 |

> 「归因分析」为什么不设独立 Agent：结果归因是「对账」的自然延伸，两者共享同一份数据（决策包 + 实际结果 + 溯源图），拆开反而要传中间状态。因此把它作为**对账官（结果归因·信用传播）**与**会话评估官（过程评估·评估器）**的显式职责，而非第 14 个 Agent。注意两者机制不同：**结果归因用信用传播（因子可验证），过程评估用评估器（过程是开放语义，套不了公式）。**

> **任务 16 · regime 维度验证的完成判据**：把 [评测集设计](/eval-dataset.html) 6.2.3 的 15 项待验证清单逐项跑完 883 天校准数据，每项产出三态结论——**✅ 纳入**（验证出与 T+N 超额有单调/可翻转关系、断点清晰、每桶 n≥5，分桶从「占位」升级「已考证」附断点+单调性证据）/ **⚠️ 待定**（数据不足无法下结论，如样本太少或断点区间 n<5；**不删除、不纳入**，挂后续动作：延长样本窗 / 换数据源 / 降级为观察项，等样本积累后再验）/ **❌ 删除**（验证出与 T+N 超额无单调/可翻转关系，从候选清单删除、不再占位）。验证通过的维度，regime 标签版本 +1。

## 任务在两条纵贯线上的归类

可观测与自进化是横切关注点，16 项任务按「可观测产出」与「进化作用」分三类：

| 归类 | 任务 | 可观测产出 | 进化作用 |
| --- | --- | --- | --- |
| 产生（写可进化层） | 1 策略、9 因子、12 大盘、2 知识、4 工具、5 资产、15 skill、16 regime | 模型调用 / 检索 / 工具调用 span | 产出候选 → 经门禁晋级 |
| 验证（冻结层 + 归因） | 3 数据、11 回测、6 对账、7 归因、10 评估会话 | 风控校验 / 判决 / 打标 span | 只读 + 归因，永不进化 |
| 触发/编排/观测 | 0 意图、8 协议、13 盘中、14 trace | 回合 / 事件 / 全 span | 触发对账、执行协议、观测底座 |

> 一句话：**「产生」类任务写可进化层，「验证」类任务冻结并归因，「触发/编排」类任务驱动前两者并铺观测底座。** 这三类在两条纵贯线上构成一个闭环。
