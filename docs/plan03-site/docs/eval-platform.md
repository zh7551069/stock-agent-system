# 评测平台接入与可观测性

> 本页讲「**结构**」：评测平台怎么接入、三层怎么切、四元 id 怎么串。三份相关页的分工：**本页 = 接入结构** · [可观测平台设计](/observability.html) = 六条可执行机制（运营化） · [自进化设计](/self-evolution.html) = 观测之后的进化闭环。三者共同构成「可观测 + 自进化」这条横切线。

## 接入方式

评测平台是**独立进程 / 独立代码仓 / 独立 DB**，通过 Trace 总线以**推送式 sink** 接入：每个 Agent 回合产出 OTLP 风格 span，写入 append-only 总线，平台采集层订阅归一化。平台对生产**只读**，写回只经「反馈层」，且只落到**过程配置仓**（prompt/skill/协议），绝不写生产数据与生产库。

## 三层结构

| 层 | 做什么 |
| --- | --- |
| 采集层 | Trace Sink / 归一化 / 哈希链落库 |
| 评测层 | 过程评测（推理质量/工具效率/协议合规/延迟/token）+ 结果评测（对账/超额/配对）+ 演化评测（新旧 A/B） |
| 反馈层 | 晋级 / 回滚判决，回归门禁 |

> **两条评测路线的分水岭（可验证性 · 权威出处）**：结果评测（对账/超额/配对）针对「可验证的因子/策略」——奖励闭式（回测能算出 T+N 超额），用规则 + 统计 + 信用传播；过程评测（推理质量/工具效率/协议合规）针对「开放的语义」——没有单一数字能概括，用**评估器**（证据/边界/判定 + LLM Judge）。同一条分水岭在进化侧就是「策略进化用信用传播、过程进化用评估器」，见 [自进化设计](/self-evolution.html)。

## 四元 id 贯穿

```
session_id → decision_id → strategy_id → factor_id
```

一条决策从"盘中触发"到"T+N 对账"到"复盘回滚"全链路用同一串 id 串起来，评测平台可任意回放任意环节。

## 可观测性四要素

| 要素 | 保证方式 |
| --- | --- |
| 全链路 span | 每回合一个 span；子步骤挂子 span；带四元 id、模型名、prompt/skill 版本、token、延迟、错误 |
| 不可篡改 | append-only + 哈希链；复盘只能基于原始 trace |
| 结果不可质疑 | 对账用实际成交与行情（前复权/涨跌停/T+1/成本口径） |
| 回归门禁 | 过程优化先影子回放、配对检验，更近真相才晋级，否则回滚 |
