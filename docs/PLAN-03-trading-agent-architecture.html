① 设计原则（先立规矩，再堆 Agent）

判决器优先、物理隔离。评测/回测/对账必须跑在与「策略生成」不同的进程、不同的代码仓、只读生产数据。生成与裁判若共享代码，会共模失效。
以「日」为独立样本，不是以「笔交易」。同一天的多只股票高度相关，不能用交易笔数虚增自由度；配对检验对齐日期交集，最小样本 n≥5。
未经严谨考证的数据不用于决策。每个字段带口径、单位、来源、复权基准；知识卡片带证据等级；校验失败即拒绝入库。
决策先看机会再看风险，用概率与权重，不做"一刀否决"。裁决面给的是概率/权重，不是二元通过。
复盘永远执行，且基于事实。市场已发生的结果不可质疑；被质疑的是我输出决策时的每一个动作、抓手与依据。调整若更偏离真相，回滚。
一切过程可回放。trace 贯穿四元 id，评测平台只看 trace 与结果，不看信念。

⑤ 模型选型（DeepSeek + 智谱）

原则：高频/例行/延迟敏感 → Flash；质量优先/深推理/意图规划 → Pro；异源交叉校验与降级冗余 → 智谱 GLM。

模型用在哪为什么
DeepSeek V4.1-Flash调度器、因子工坊、盘中哨兵、数据管家、能力管家、回测解读便宜 3–4 倍、并发 2500、输出短、支持视觉（读图表/截图）
DeepSeek V4-Pro主控（意图/规划/整合）、策略师（定稿）、大盘分析师、对账官、会话评估官、资产蒸馏更强 agentic 编码与难推理，质量优先；无视觉，喂文本/结构化数据
智谱 GLM-5.3-flash / flashx因子解读批量、数据 QC 第二遍、盘中哨兵降级冗余高吞吐低成本，DeepSeek 限流/故障时兜底
智谱 GLM-5.3会话评估官、知识馆长的异源第二意见两家厂商交叉校验结论，降低"同一模型家族共同错误"
⚠️ 模型版本号按你本地网关目录里实际可用的为准（GLM 名称取自你 gateway 的模型清单）。选型是占位建议，正式定版前用同一批任务对 Flash/Pro/GLM 做一次配对 A/B，以实测差距为准，不以宣称的 benchmark 为准。

⑥ 决策生命周期（主控规划 → 回测验证 → 对账回滚）

⑦ 评测平台怎么接入（保证会话过程可观测）

接入方式

评测平台是独立进程/独立代码仓/独立 DB，通过 Trace 总线以推送式 sink接入：每个 Agent 回合产出 OTLP 风格 span，写入 append-only 总线，平台采集层订阅归一化。平台对生产只读，写回只经"反馈层"，且只落到过程配置仓（prompt/skill/协议），绝不写生产数据与生产库。

三层结构

采集层 Trace Sink/归一化/哈希链；评测层 过程评测（推理质量、工具效率、协议合规、延迟、token 成本）+ 结果评测（决策对账、超额、配对）+ 演化评测（新旧版本 A/B）；反馈层 晋级/回滚判决，回归门禁。

四元 id 贯穿

session_id → decision_id → strategy_id → factor_id

一条决策从"盘中触发"到"T+N 对账"到"复盘回滚"全链路用同一串 id 串起来，评测平台可任意回放任意环节。

⑧ 可观测性：怎么保证"看得见、可回放、可质疑"

全链路 span

每个回合 = 一个 span；子步骤（推理块、工具调用、子代理）挂成子 span；span 带四元 id、模型名、prompt 版本、skill 版本、token、延迟、错误。

不可篡改

trace 总线 append-only，每条事件带哈希链；评测平台落库时校验，防止"事后改过程"——复盘只能基于原始 trace。

结果不可质疑

对账用实际成交与行情（前复权、涨跌停、T+1、成本口径），结果定了就是定了；被质疑的是决策时的动作与依据。

回归门禁

任何过程优化（改 prompt/skill/协议）都要先跑"影子回放"：用历史 trace 重放，配对检验新旧结果，只有更接近真相才晋级，否则回滚。

⑨ 多 Agent 交互协议约定（任务 7）

协议是版本化治理工件，不是某个 Agent 每次临场决定的东西。设计一次、机器校验、违规即告警。

协议层内容校验方
消息信封每条消息：四元 id + 来源 agent + 目标 agent + 消息类型 + schema 版本 + 时间戳 + 幂等键协议总线（进总线即校验）
消息类型事件 / 命令 / 请求-响应 / 发布-订阅，各带优先级与超时调度器
决策包契约策略 proposal 与决策包是机器可读 JSON Schema：信号、进场、出场、仓位、风控门、每个抓手/依据的引用（因子 id / 数据口径 / 知识卡片 id）回测判决官 + 对账官
数据口径契约复权基准、单位、日期格式、涨跌停、T+1、板块归属，全部带 id 与版本数据管家
写域隔离每个 Agent 只能写自己的状态；裁决面只读生产；评测平台只写过程配置仓协议总线（ACL）
异步/同步盘中路径同步低延迟（哨兵→主控→调度→执行）；盘后/回测/对账/评估走异步队列调度器（预算与限流）

⑪ 落地路线（先判决器，后决策面）

阶段做什么完成判据
P0 判决器回测判决官 + 对账官 + 数据口径契约 + Trace 总线。先把"怎么算对"立起来。oracle 测试能识别正 alpha；独立日 ≥30；配对检验可用

P2 决策面 + 主控主控、调度器、策略师、因子工坊、大盘分析师、盘中哨兵。主控规划可落地；策略 proposal 可被判决官直接消费
P3 评测平台采集/评测/反馈三层 + 过程资产 + 会话评估官 + 影子回放门禁。任意决策可回放；A/B 回归门禁生效
P4 自我进化全链路闭环：trace→分析→优化→回放验证→晋级/回滚。过程变更皆有证据，更差自动回滚

⑫ 风险与反模式（来自已踩过的坑）

判决器与选手共模。评测和生成共用数据/代码/假设 → "测试全过但决策没用"。→ 物理隔离 + 只读 + 独立样本定义。
用交易笔数当样本。同日股票相关，自由度虚高，t 值假显著。→ 以日为样本，配对对齐日期。
未剔 beta 就报超额。把 beta 当 alpha。→ 超额对沪深300剔 beta；并配同天随机对照。
数据口径漂移。前复权 vs 涨跌停价、元/万元、东财 vs 同花顺混用。→ 口径契约 + QC 门禁。
为一点风险否决全部 / 为一点机会否决卖出。→ 概率权重判断，判决器输出概率而非二元。
主控越权直接写生产。主控只规划整合，不落库、不写判决库；写域由协议总线 ACL 强约束。
