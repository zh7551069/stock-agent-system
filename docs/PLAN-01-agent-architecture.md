## 0. 结论摘要

**一句话**：把"判断"和"正确性"物理切开——LLM 只产出**概率化、证据化、可审计**的决策卡，
正确性由已冻结的 qbt 引擎（RiskChain / Matcher / Ledger）负责；agent **无特权路径**；
**复盘是一条会产出「变更提案 + 历史回放验证 + 自动回滚」的工程流水线**，不是写感想。

**四条主设计决策**

| # | 决策 | 依据 |
|---|---|---|
| **1** | 复用 qbt 引擎，不重造 | 实测 `tests/` **101/101 通过**；数据层只读冻结；其"逐位可复现"是复盘进化能成立的前提 |
| **2** | 判断层输出**概率+权重+期望值+证据卡**，不输出"结论" | 用户要求"任何决策都要通过概率、权重来判断"；概率可被 Brier score 客观校准 |
| **3** | 任何单一证据（无论正反）**无否决权** | 用户明确要求 + 知识库血证：`E-1 用与资金形态无关的指标否决资金验证通过的机会 ≥6 次` |
| **4** | 复盘产出**CP 卡 + 四重门 + 自动回滚**，门 3 以 **151 条历史错误清单**为回归基线 | 用户要求"变差就回滚""不能改掉新问题老问题又出来" |

## 2. 第一性原理与总体架构

### 2.1 为什么这样切

用户要求里有**一对张力**：
- 「进攻、果断、接受赌博、概率权重」→ 需要**不确定性下的判断**、裁量、快。
- 「数据严谨、求真求实、强制复盘、可回滚进化」→ 需要**确定性、可审计、可统计**。

旧方案把两者混在一起，**把正确性寄托在"模型看得见规则"上**，而实测否证了这条路
（`TOOLS.md` 会话仅加载 42%；注入 20k 截断致 58% 内容决策时不可见）。
qbt 已给出正确公理：

> **不可违反的性质，必须由类型、接口与不变量保证，不能由文本约束保证。**
> **模型是系统的一个客户端，不是正确性的来源。**

### 2.2 为什么不拆多体（**关键取舍**）

知识库《量化策略Agent-v2.0.1》提出 `Orchestrator + 4 专家 + Critic`，但其自家落地评估的结论是：

> "正确路径是**先补 ②③ 的工程骨架**，再谈专家分工；**不是先拆 agent**。"
> "心法整篇讲的是'怎么把单体做可靠'，**没有一句支持'拆成多体'**。"

本方案采纳该结论，并给出更强理由：
1. 151 条错误中**没有一条**的根因是"专家不够多"；根因是**否决无分级、规则加载不全、没有闭环、证据无背书**。
2. 多体引入**上下文传递损耗**，与 §1.3 的静默错误叠加 → 更难审计。
3. 引擎已提供"**结构化流水线**"这一更强的替代：`Score → Allocation → OrderIntent → RiskChain → Order → Matcher → Ledger`。
   把"专家分工"换成"**可单测的纯函数 + 可审计的闸门**"，得到同样的职责隔离且**可逐位复现**。

**但保留 Critic 的实质**：不是"另一个 agent"，而是**独立上下文的校验器**（§4.6），
因为它解决的问题（"同一上下文里既生成又自审，模型会为自己的结论找理由"）是真实的。

### 2.3 总体架构（闭环）

```
        ┌──────────────────────── 闭环（进化） ────────────────────────┐
        │                                                              │
   L2 事实感知           L3 判断               L1 执行          L4 复盘
 context/  ──证据卡──▶ judge/ ──决策卡──▶ 引擎 ──账本──▶ review/
 数据闸门              概率/权重           RiskChain       冻结/归因
 六类Context           期望值/失效条件     撮合/账本        CP卡/四重门
        ▲                                                         │
        └──────── 知识库(vault) + 结构化记忆(表) + 参数库 ◀────────┘
```

**单向、无特权**：判断层只能提交信号；信号必须穿过 `Allocation → RiskChain → Matcher → Ledger`；
判断层**不能**改账本、不能跳风控、不能盘中下单。

### 2.4 六条不可协商的约束

| # | 约束 | 落地 |
|---|---|---|
| A1 | 判断与正确性分离 | 决策卡 → `SignalProvider`，无特权 |
| A2 | 确定性可复现 | 一切 LLM/网络调用录制进 run，回放不重调 |
| A3 | 结构性无未来函数 | 决策有 `cutoff`，只读 as-of 快照（血证 `C-09`：+34% → −2.78%） |

| A6 | 失败即停 | 数据缺口日 fail-closed，不降级跑 |

### 2.5 三基座裁决（**本方案最关键的未决问题 → §12-D8**）

现状是**同一个目标存在三代实现**，且都没有被"官方"选定为基座。这必须先裁决，否则实施会分裂。

| 基座 | 强项（实测） | 弱项（实测） | 本方案初判 |

## 3. L2 事实感知层详设

### 3.1 数据闸门 DataGate（先于一切判断）

```python
@dataclass(frozen=True)
class Field:
    name: str; value: Any; unit: str
    source_table: str; source_columns: tuple[str, ...]
    as_of: dt.date
    freshness_ok: bool       # 运行时实测 max(日期列)，不用 table_meta（T9）
    normalized_ok: bool      # 已归一到 股/元/date/单一口径
    status: str              # PASSED | UNVERIFIED | MISSING
```

**六道校验**（任一不过 → 该字段 `UNVERIFIED`，权重强制 0，写 `gate.json`）：

1. **表白名单**：显式扩展 `ALLOWED_TABLES`，逐表写理由（红线 2）
2. **新鲜度**：实测 `max(日期列)`，每表独立阈值（**禁用 `table_meta`**，T9 已失真）
3. **存在性**：行数 0 → `MISSING`，**绝不转 0**（T1 / B-15）
4. **非空返回**：区分"合法为空"与"口径错致空"（T2）→ 口径未命中即报错
5. **类型/单位归一**：4 种日期格式 → `date`；4 种金额单位 → 元；VARCHAR 数值严格 cast，失败即 UNVERIFIED（T4/T5/T6）
6. **口径锁定**：同一指标只认一个源（东财 or 同花顺）；跨源只做交叉校验，不进打分（T8）

**产出**：`agent/state/context/<date>/<cutoff>/gate.json`，逐字段可审计、可复算。

**"可用数据日"（T10 落地）**：按**实测有数据的交易日**决策。
2026-10-12：`lhb_daily` 可用、`daily/minute/limit_price/moneyflow` 不可用 → 当日**只能**出龙虎榜维度结论。

### 3.2 六类 Context Builder（as-of 严格）

| Context | 数据源 | 核心量 |

## 4. L3 判断层详设

### 4.1 证据卡（机械可校验，杜绝"编数据"）

```json
{
  "evidence_id": "EV-20261009-FLOW-0007",
  "claim": "动力电池回收板块主力净流入43.61亿，全市场第3，较昨日第115名跃升112位",
  "source": {"table": "board_flow_em", "columns": ["主力净流入净额(元)"],
             "date_col": "交易日期", "as_of": "2026-10-09", "convention": "bigint_date"},
  "value": {"net_inflow": 43.61, "unit": "亿元", "rank_today": 3, "rank_prev": 115},
  "gate_status": "PASSED",
  "derived_by": "agent.context.flow.board_rank_shift@1"
}
```

**硬规则**：只能引用**本次 context 快照内存在且 `gate_status == PASSED`** 的 `evidence_id`；
引用不存在 / 未通过闸门的字段 → **决策卡校验失败，拒绝产出**。
→ 把"编数据"从靠人盯变成**机械可检出**（血证 `B-17`、根因 D）。

**每条证据必须标注**〔已验证 / 推断 / 未证实〕，`未证实` 条目**不得作为唯一定性依据**（继承 v2.0.1 契约）。

### 4.2 概率情景（把"赌博"量化）

决策卡必填，缺一即校验失败：

- 2–4 个**互斥**情景 + 概率（Σ ≈ 1）
- 每情景目标价与路径
- 胜率 `p`、盈亏比 `R`、期望值 `E = p·R − (1−p)`
- **多窗口方向概率**：**1 / 3 / 5 / 10 / 20 日五档**（继承知识库"多窗口决策卡"实证：买信号 1–3 日就强，卖信号 10–20 日才强）
- **动作门槛**：`E > E_min` ∧ `p ≥ p_min` ∧ **`独立日 ≥ 30`** ∧ `max|超额| ≥ 0.30%`（2× 摩擦成本）
  阈值全部进 manifest，可被消融验证

> 直接落地"任何决策都要通过概率、权重来判断"；同时用 **独立日 ≥30** 门槛
> 解决实测问题（2 连板仅 3 个样本不能当规律；龙虎榜 n=28/独立日 22 → 只观察）。

### 4.3 分项加权总分（可归因、可消融）

```
total = w1·大势 + w2·情绪 + w3·资金 + w4·题材 + w5·个股 + w6·消息 + w7·信号库 − risk_discount
```

- **`w7·信号库`** 直接挂载 30 信号权重（A/B/C 级 ×1.0/×0.7/×0.3；D 级弃用 + **反向警示**，如 X07）
- **分项得分与权重全部落盘** → 赛后能回答"哪个分项赚的钱"
- 初始权重**不拍脑袋**：以 §1.6 实证为**先验**，再用历史回放做网格/贝叶斯优化，且**必须过四重门**
- 缺失分项 → 权重归零并**重新归一化**，同时决策卡显式标注（不静默）

### 4.4 反面证据：进折扣，不进否决（决策 #3 的落地）

- **任何单一证据（无论正反）都没有否决权** —— 由 schema 强制（证据卡**没有** `veto` 字段，物理上表达不出否决）
- 反面证据只进入 `risk_discount = f(数量, 加权强度)`，影响总分与仓位上限
- **唯一的硬否决来自引擎 `RiskChain`**（可交易性/整手/T+1/资金/涨跌停/停牌/限额/熔断）—— 物理约束，非观点
- **合法看空/否决依据白名单**（继承 `E-2`）：①资金流反向 ②量价结构坏 ③日线趋势坏（买入侧 +④大盘单边破位）
- **禁止作为否决理由**（继承 v2.0.1 契约 A.3）：估值 PE/PB、"破 BOLL 上轨"、"日内已涨 X%"、"位置高"、**"板块不共振"**、"组内最弱"、"跟风票"
  （血证 `A-30`：用"板块不共振"否决中国船舶 → 9/7–9/10 船舶 +6.36% vs 新五丰 −4.75%）

### 4.5 决策卡（结构化落盘，必填）

继承并强化 v2.0.1 的**五段契约**（顺序不可变）：

1. **动作**：买/卖/持有/观察 + 标的 + 数量（含最小申报单位校验，血证 `A-44` 科创板 200 股）
2. **依据**：≥3 条，每条带 `evidence_id` + 来源 + `as_of` + 〔已验证/推断/未证实〕
3. **执行参数**：价位区间、时间窗口、条件单
4. **失效条件**：**必须可观测**（价格/资金/时间），不能写"情况变化则作废"
5. **风险与仓位**:本次操作后仓位变化、集中度影响、单票上限（默认 **15%**）

**本方案额外强制**：
- **计划 vs 实际**（由引擎回写：成交/拒绝原因/T+1 顺延/仓位被 clamp 后实际值）—— **复盘的核心输入，非可选**
- **反面证据 ≥1 条** + **杀死理由 3 条**（继承 `D12`，少于 3 条或写不出 = 拦截）
- **"不减/持有"必须同时给出冲高减仓条件单**（继承契约硬性要求）
- **向上目标 T1/T2 必填**（继承 `D17`）

### 4.6 LLM 的无特权接入 + 独立校验器

- 实现 `SignalProvider`，与手工信号走**完全相同**的 `Allocation → RiskChain → Matcher` 路径
- 全部调用**录制**（引擎已支持；实测 276 次调用全回放、0 次真实调用）
- 超时/失败 = `missing`，**missing ≠ 卖出**，组合层显式处理
- **预算与速率**：候选池 ≤ N 只、单分钟调用上限、每日 token/费用上限、不做全市场扫描
- **注入防护**：行情/新闻文本一律视为不可信数据；LLM 输出一律视为不可信输入
- **独立上下文校验器（Critic 的实质）**：**独立上下文 + 独立提示词 + 独立进程**，
  校验项 = `critic_evidence` 的 6 项（①节点完整性 ②rc 语义一致 ③四要素缺 ④违规否决词 ⑤闭环缺口 ⑥证据无背书）
  → 直接继承知识库已落地且"首扫 6 项全为真阳性"的实现
- **准入**：任何 LLM 信号必须先过回测评估（含消融与稳定性）才允许进模拟盘

## 5. L4 复盘进化层详设（差异化重点）

用户对复盘的要求最重，也最难；而这恰是旧体系最大缺陷（**31% 建议无事后追踪**）。

### 5.1 事实冻结 Outcome Freeze

T+1 / T+3 / T+5 / T+20（与五档窗口对齐）收盘后自动跑：
用**账本 + 行情**算实际结果（绝对/相对收益、剔 beta 超额、最大浮亏、是否触发失效条件、是否被拒/顺延）。

> **铁律：市场已发生的结果永远不可质疑，只记录、不解释。**
> 落地：`outcome` 表 **append-only**，任何修改留痕。

### 5.2 抓手归因 Attribution

| 抓手 | 判定方法（客观） | 证据来源 |
|---|---|---|
| **数据** | 该字段当时是否 `freshness_ok`、是否踩 T1–T11 | `gate.json` |
| **脚本/工作流** | 取数逻辑有无 bug | 回归测试（每个已发现 bug 固化一条 fixture） |
| **知识/规则** | 引用的是哪条笔记/卡、是否误读原文 | vault `path#section` 对照 |
| **判断** | 概率校准：预测 0.35 的事件实际发生频率 | **Brier score / 校准曲线** |
| **权重/参数** | 各分项与逐信号贡献 | 消融表（`qbt cli ablate`） |
| **执行** | 计划 vs 实际偏差（含被拒与 T+1 顺延） | 账本 `events` + `intents` |
| **闭环** | 本条决策是否有 outcome 记录 | **覆盖率强制 ≥100%**（治 31% 无追踪） |

> 用户要求"完成这个动作的每一个抓手或依据是否可靠" —— 上表枚举完备，且**每类都有非主观判定方法**。

### 5.3 CP 卡 + 四重门 + 自动回滚

**CP 卡（Change Proposal）**：
```
假设 → 影响面 → 验证区间(必须含调整前样本) → 验收指标 → 回滚条件
```

| 门 | 内容 | 判据 |
|---|---|---|
| **门 1 无回归** | 全量历史指标不劣化 | 劣化不超阈值；含**剔 beta 超额** |
| **门 2 目标改善** | 针对指标显著改善 | **独立日 ≥30** + 置信区间 + `max|超额| ≥0.30%`；不显著不算过 |
| **门 3 无新问题** | **151 条历史错误清单回归为空** | 老问题复发 or 带出新问题 → **直接失败** |
| **门 4 样本外** | holdout（Purged/CPCV + Embargo）不劣化 | 防过拟合 |

**结果处理**
- 四门全过 → 版本 +1，写 `evolve/CHANGELOG.md` + 证据 `run_id`
- 任一门失败 → **自动回滚**到上一版 `manifest` hash（引擎确定性使精确回滚可行）
- 失败调整写入 `evolve/FAILED.md`（**负结果留档**）；**同一假设无新证据禁止重复提出**

> 直接回答用户两条要求：
> ① "调整离事实更远就回滚重来" → 门 1/门 4 + 自动回滚
> ② "不能只顾当下要看历史；不能改掉新问题老问题又出来" → **门 3 用 151 条真实错误做回归** + 门 4 holdout

### 5.4 记忆分工（不许互相替代）

| 记忆 | 形态 | 用途 | 规则 |
|---|---|---|---|
| **Obsidian vault** | 人读 markdown（2238 卡 + 17 总纲 + 8 手册） | 心法、案例、纪律、复盘日记 | 构建期生成 `knowledge_index.json`；**引用必须给 `path#section`**；未命中即报错；**禁止整库注入**（血证：全量需 171.7× 上限） |

## 6. Agent 设定（心法必须参数化，否则不许进代码）

**落地原则：每一条心法必须映射为可测量的参数或规则，否则不许进决策代码。**
这是"求真求实"对心法的约束。下表的参数值**全部来自 §1.6 实证**，不是自拟。

| 心法 / 原则 | 出处 | 落地参数（可测量） |
|---|---|---|
| **资金为纲** | vault《第一原理》 | 资金流为最高权重分项；主判据 = 板块净额 + **排名迁移**；**主力资金次日延续率仅 18% → 禁止单日资金当趋势**（"至少看 3 日序列"） |
| **观天之道，执天之行** | 《阴符经》 | 先定 regime → regime 决定总仓位上限；**涨停家数 <30 = 唯一正收益区；>120 = 过热崩盘前兆** |
| **阳极必衰 / 阴极必盛** | 《周易》 | 情绪温度计**分位数极值反转**；**高潮板块次日 80% 熄火；板块做多 90% ≤4 天** |
| **群体恐慌时贪婪** | 用户要求 | 情绪分位 < X 且跌停潮 → 逆向模块（独立预算、独立归因）；**但 T-1 跌>2% 当日信号降级等一日（D5）** |
| **集中优势兵力打歼灭战** | 毛泽东思想 | 候选池收敛到**轮动指数 >0.15 的主线**；单票上限 15%、持仓数少 |
| **打得赢就打，打不赢就走** | 十六字诀 | 失效条件触发即走；**止损位距支撑 ≥1×ATR（D16）**；**到价即执行无需确认（D8/D15）** |
| **实事求是 / 调查研究** | 毛泽东思想 | 数据闸门 + 证据卡引用制（§3.1 / §4.1） |
| **不打无准备之仗** | 毛泽东思想 | **买入前写 3 条杀死理由（D12）**，写不出 = 拦截 |

**进攻型风格的参数化**（全部进 manifest，可消融）：
`max_gross_exposure = 0.95`、单票上限 15%、持仓数上限偏高、允许追高（**带封单/换手约束**）、
止损快、无最低持有期、候选池偏涨停梯队与资金流入前列、做T资金 ≤ 总仓 1/3~1/2。

**三条"反人格"约束**（防止进攻型失控）：
1. 不因为"想进攻"而降低数据门槛 —— 数据不过闸门，宁可不出手
