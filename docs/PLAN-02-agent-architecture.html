6 · 判断层：概率与权重

图 8 · 判断流水线。「独立日 ≥ 30」这条门槛直接用实测教训：2 连板当天只有 3 个样本，不能当规律
决策 #3：任何单一证据（无论正反）都没有否决权

落地方式是物理的：证据卡的 schema 里根本没有 veto 字段，模型在结构上就表达不出"因为一个风险点，否决所有买入"。反面证据只进入 risk_discount = f(数量, 加权强度)，影响总分与仓位上限。

唯一的硬否决来自引擎 RiskChain（可交易性 / 整手 / T+1 / 资金 / 涨跌停 / 停牌 / 限额 / 熔断）——那是物理约束，不是观点。

依据：autoclaw 自查的 E-1 记录「用与资金形态无关的指标否决资金验证通过的机会」重复 ≥6 次，最严重一天 6 次（9/11 亨通 / 山东玻纤 / 中兵红箭），事后山东玻纤 +4.05%、亨通 +1.02%。

✅ 基座之一的实测判决：alphadesk 不是空壳（2026-10-12 实跑）

757 个用例（parametrize 展开后）→ 749 通过、8 失败。过程本身有一次必须记录的自我更正： 首次在我的受限沙箱下跑，失败 17 项；其中 9 项是沙箱拦截写入造成的假故障（如 state/trace.jsonl 的 PermissionError、trading.db 的 unable to open database file）。 给足权限重跑，这 9 项全部通过。

剩余 8 项失败的根因分类：

  • 7 项 = 测试保质期问题，非代码缺陷。断言把 2026-09-24 的实盘快照写死了： latest_trade_date() == 2026-09-24（现实已是 10-12）、holdings == 31 行（现实 40 行）、 长飞光纤 qty == 500（现实 100）、10/10 张表陈旧（现实 3 张）。
  • 1 项 = 真实分歧：test_sql_matches_pandas_real_db —— panel 的 SQL 快路径遇到重复 (code,date) 键时回退 pandas，与 pandas 结果不一致，值得单独查。

结论：alphadesk 可作为「参考实现」复用其契约、工具定义与验证方法论（尤其它"对着真库做集成测试"的意图是对的，只是把值写死了）； 但它的能力数字必须自己复跑，不能引用文档自述——文档里同时存在 738 与 672 两个数字，而实测收集数是 757、静态函数数是 658。

⚠️ 更正记录：我此前把 trading.db 打开失败诊断为「WAL 模式 + 所在目录不可写」，该结论是错的——那是我的沙箱在拦写操作，不是操作系统权限问题。给足权限后 alphadesk 的持仓链路测试全部通过。

10 · 环境与依赖现状

图 14 · 环境已就绪。Python 3.11.16 的理由：scikit-learn 1.9.1 要求 >=3.11，且你自己两个成熟工程（alphadesk / vibe-astock）都跑在 3.11.16；系统默认的 3.14.7 太新
安装中发现的两个真实问题（都已解决，记录备查）

① ~/.cache 属主是 root（drwxr-xr-x root staff）→ 用户无法在其中创建目录 → uv 默认缓存初始化失败（Permission denied）。
解决：改用 UV_CACHE_DIR=~/.uv-cache，与你既有的 ~/.npm-cache-qqbot、~/.npm-cache-vibe 约定一致。

② purged-cross-validation 是错的包名——PyPI 上实际叫 purgedcv。装前逐个校验包名（HTTP 状态 + requires_python）避免了这个坑，也顺带确认了 scikit-learn 的 3.11 下限。
